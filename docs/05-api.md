## Conventions

- JSON, `camelCase` fields, plural kebab-case paths.
- `GET` list, `POST` create (201), `GET /{id}`, `PATCH /{id}` partial update,
  `DELETE /{id}` (204). Actions are `POST /{id}/{verb}`.
- Ids are integers, except user ids (text, from the auth library).
- Timestamps are UTC ISO 8601.
- Secrets are never returned. Responses carry `hasApiKey: true` instead.

## Errors

RFC 9457 problem details, `Content-Type: application/problem+json`:

```json
{
  "type": "https://unseen.invalid/problems/validation",
  "title": "Validation failed",
  "status": 422,
  "code": "validation",
  "detail": "name must not be empty",
  "errors": [{ "field": "name", "message": "must not be empty" }]
}
```

`code` is a stable machine-readable string. The frontend switches on `code`.

| Status | When |
|---|---|
| 400 | Malformed request |
| 401 | No valid session or API key |
| 403 | Authenticated, permission missing. Body names the required permission. |
| 404 | Resource does not exist |
| 409 | Conflict, for example duplicate TMDB id |
| 422 | Validation failed |
| 502 | An external service failed (TMDB, indexer, download client) |

A user without `library:read` gets 403 on a movie, not 404. Open question:
hide existence with 404 once per-library scoping exists.

## Pagination

`?page=1&pageSize=50&sort=title&order=asc`. Response:

```json
{ "items": [], "page": 1, "pageSize": 50, "total": 0 }
```

Maximum `pageSize` is 500. The movie list may return everything when
`pageSize=0`. Open question: confirm, or always page.

## Permissions per route

Each handler declares one permission through the extractor, and the same
value is written into OpenAPI as `x-permission`:

```rust
#[utoipa::path(get, path = "/api/v1/movies", extensions(("x-permission" = json!("library:read"))))]
async fn list_movies(_: Require<LibraryRead>, ...) { ... }
```

The exact Rust shape is decided in M1. Requirements:
- exactly one permission, or an explicit `Public` marker;
- a test walks the router and the OpenAPI document and fails when a route
  has neither, or when the two disagree.

## SSE

`GET /api/v1/events`, `text/event-stream`. Events are filtered by the
caller's permissions at send time.

| Event | Data | Permission |
|---|---|---|
| `download.progress` | id, progress, speed, eta, state | `queue:read` |
| `download.state` | id, old state, new state | `queue:read` |
| `movie.updated` | movie id | `library:read` |
| `task.status` | task name, status | `system:tasks` |
| `permissions.changed` | none; the client reloads `/me` | any authenticated user |

Reconnect uses `Last-Event-ID`. Open question: replay buffer size, or state
resync by refetching.

## Versioning

`/api/v1` changes only in backward-compatible ways after V1. Before V1,
breaking changes are allowed.
